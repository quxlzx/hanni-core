# Practical work planning

Identify the requested outcome, fixed deadlines, available time, and known
dependencies. Use supplied tasks and connected records that are accessible;
do not claim to have read a task system that is unavailable.

Prioritize by deadline, consequence of delay, and dependency rather than marking
everything urgent. Separate required work from optional improvements. Break large
tasks into steps with observable completion criteria. Label effort estimates as
estimates and allow time for interruptions when creating a daily schedule.

If the workload does not fit, show the conflict and propose what to defer or
renegotiate. Preserve the user's chosen priorities. Ask only for missing constraints
that materially change the plan; otherwise state reasonable assumptions.

Return the ordered plan and the first useful action. A proposed plan is distinct
from saved task records. When the user asks to create or update tasks, inspect the
available tool schema, avoid duplicates, and verify the saved result. Use the
recurring-tasks skill for explicitly requested recurring automation.
