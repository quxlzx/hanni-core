# Campaign 6: distributed cluster and GPU validation

The baseline is the current checkout, including uncommitted Campaign 4 and 5
repairs. Preserve prior campaign files, owner configuration, databases, model
defaults and independently managed processes. No separate common campaign file
was found; the explicit common evidence, isolation, prospective annotation,
independent verification and checkpoint rules from the prior campaigns apply.

Two actual engineering agents inspect cluster/telemetry and distributed
scheduling. An actual independent verifier seals fresh private controlled
scenarios before repairs, reproduces exposed failures before architectural
fixes, and executes the final suite once after a source freeze. Separate
development controls may guide repairs. Final inputs, answers and author code
are verifier-owned; they never guide engineering. The manager integrates and
owns initial live probes. Each implementation/verification cycle has a durable
checkpoint with exact source, command and result provenance.

Discover nodes and workers dynamically from existing protected deployment
data. Use the original strict SSH/Tailscale options, existing identity/agent and
secure provider authentication. Never embed or print passwords, API keys,
authentication headers, raw environments or login URLs. Roster-projected
Tailscale state, classified errors and hashes are permitted evidence. A TCP
connection is connectivity evidence, not authenticated SSH or verified hardware.

Use isolated exact copies of deployment/context files for native registries and
owned SQLite storage. Owner memories and workflow databases are not opened.
Actual endpoint requests use original protected transports and controller
privacy/resource/context gates. No edited model labels, invented proofs,
resource reserves or historical observations authorize live serving.

Live defaults: at most two concurrent read-only node probes, one SSH operation
per node at a time, 0.6-second TCP checks, 12-second owned SSH command deadlines,
two roster rounds, and no continuous cluster monitor. Hardware collection uses
bounded standard-library scripts and read-only existing GPU tooling. Existing
services are inspected in place. No installation, driver changes, reboot,
sleep, configuration overwrite or independent process termination is allowed.
Only campaign-owned local test/SSH processes may be cleaned up.

Generation defaults, where original admission permits: at most 30 actual
generation requests in the entire manager live run, at most ten per worker,
at most two concurrent requests globally and within each worker's configured
capacity, temperature zero, output at most 128 tokens, and a 180-second total
per-worker serving budget. All prompts are synthetic. A cancellation closes
only the owned request/connection; it does not imply confirmed server-side GPU
preemption. No indefinite memory pressure or all-GPU stress is introduced.

Context stages are 8K, 16K, 32K, 64K and 128K total input/output allocation.
Progress only after a lower stage's genuine accounting, exact source retrieval,
current model/runtime identity, observed resource reserves and configured/
reported allocation pass. Reserve output within each stage and disclose actual
prompt tokens, completion tokens and combined allocation. Unsupported stages
are skipped with a reason. Configured 131072 is not proof of 128K retrieval.
The original bounded context-proof API may impose a smaller payload/target
ceiling; honor it and report the limitation. No service is loaded or restarted
solely to create an eligible test. Inspect existing IQ3_S files/deployments
where available, without silently relabeling Q4_K_S registrations.

Development has at least 50 prospectively authored isolated scheduling
scenarios across correct selection, unavailable/busy workers, excessive context,
insufficient VRAM, multiple eligible workers, parallel tasks, queue saturation,
safe reassignment, network interruption and result verification. Supplemental
cancellation, heartbeat, GPU-assignment and workflow controls are allowed.
Disposable HTTP providers and leaf observations exercise the real implementation
but are controlled tests, never live GPU/model passes. Fault simulation must
not disconnect owner endpoints or create duplicate consequential writes.

Report every configured node and worker with current evidence and denominators.
Distinguish configured model/GPU/context from independently observed or verified
values. Measure real prompt/generation speed, inference latency P50/P95, peak
VRAM, errors and availability only from applicable actual observations.
Outside-inference resource samples are headroom, not peak inference cost.
Refused generation has no model answer and null quality/speed/token metrics.
Controlled scheduling success is separate from live distributed workflow
success. Independent verification must confirm important live hardware and
inference claims or leave them unverified. Preserve failed runs and raw
provenance; final once-only results cannot trigger tuning. Changes remain
uncommitted unless the user asks for a commit.
