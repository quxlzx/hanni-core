# HANNI V3.6 full-system validation

Final disposition: **PARTIAL; reliability acceptance is not met.** Actual HANNI
works for many individual diagnostics, isolated local operations and native
desktop interactions. Its configured 4B assistant still chooses incorrect tools,
produces unsupported conclusions and failed the three actual persistent goals.
The repaired backend and attractive desktop do not establish a reliable
autonomous personal assistant.

This campaign used exactly three actual agents: manager, engineer and independent
verifier. The original controller, configured cached Qwen3.5-4B-Q4_K_M model,
registry, policy and native Windows client were exercised. Source configuration,
model selection, personal data and closed LAYA rollout gates were preserved.
There was one serialized local inference runtime. No publication or push occurred.

of implementation checks. They are **not a 100% live functionality claim**. Live

to a separate temporary integration registry and are closed, not configured
production integrations.

## Remaining failures and blockers

The most consequential weaknesses are incorrect tool selection, unsupported
interpretation of tool evidence, unreliable persistent planning, absent
conversational authority for private desktop mutations, and unverified optional
intelligence/hardware integrations. Examples from the sealed final cohort:
processor use became a process-memory listing, today's date became a Google
agenda offer, a file digest became a hash of its pathname, and largest-file
conclusions were guessed from names without measured sizes. These are actual
assistant failures retained for future development, not solved by formatting.

Three actual persistent goals failed: folder analysis/report planned a directory
as an ordinary file; the local task sequence produced an invalid bounded plan;
the memory report proposed unrelated system/model diagnostics and was cancelled
before execution. The backend's checkpoint, ownership, restart, cancellation,
permission and readback tests passed independently. They do not repair model
planning or justify an autonomous-completion claim.

Private desktop mutations have a separate owner-confirmed registry. They passed
real isolated stores and native interactions but are not exposed to chat. Their
model-selection tests remain BLOCKED; actual diagnostic model responses do not
execute those operations. Existing conversational policy similarly blocks many
local/task/sensitive writes. Those gates were retained.

Black and Ruff are missing in the current interpreter, so `project.format` and
`project.lint` remain BLOCKED. Real Spotify volume readback has a missing optional
dependency; its original handler was additionally verified with a controlled
pycaw boundary. No package was installed solely to inflate coverage.

## Integrations, memory and hardware

Google: original adapters passed 12 dedicated calendar/integration tests covering
discovery, agenda, next event, create/readback, missing auth/scopes, invalid dates,
time zones/DST, timeout and duplicate uncertain-write suppression. The broader
inventory also covers original Gmail/Drive/Docs/Tasks adapters with controlled
providers. Live authentication/API remains BLOCKED. Initial discovery exposed a
global Windows credential-vault boundary despite temporary local state; testing
was relaunched with an explicit empty external vault. No live provider request or
credential modification was made. Optional SQLite calendar is deferred as a
separate feature; existing support was preserved.

MCP: an actual SDK stdio server dynamically supplied status, echo and a durable
create-record capability. All three valid original-registry calls and invalid
argument rejections passed. The confirmed write was independently read back.
The actual resident model selected/executed both read tools, 2/2. The write tool
remained blocked by the original model policy. Reconnection/schema revisions,
permission gates and cleanup are independently checked; third-party credentials
are unnecessary. Temporary fixture definitions are in the separate MCP manifest.

Memory: real isolated retrieval, continuity, provenance, corrections, deletion,
review, owner authority and process-recovery checks were exercised. The final
actual response cohort met four of five memory-grounding expectations; its
remaining ambiguity failed honestly in the scoring. LAYA is disabled/unavailable
in this installation; its shadow/advisory logic tests are controlled evidence,
not proof of active production retrieval or an available LAYA model.

Voice: device discovery found 15 input devices; installed SAPI voices were
enumerated, and the configured Australian voice was absent. Original cached
Silero/faster-whisper silence behavior was tested. The owner-authorized capture
closed after 10.047 seconds, 310 chunks, zero dropped blocks and no detected
utterance. The owner then clarified that the microphone is inactive. Acoustic
recognition, wake/relevance, audible output and acoustic barge-in remain BLOCKED;
the original raw result and classification erratum are preserved. No raw audio
or transcript was saved. Prior microphone success is owner-reported history,
not current validation.

Screen awareness: the actual adapter reports no registered screen-capture/vision
pipeline. Capture-disabled behavior and privacy state are explicit. Vision
inference, screenshot expiration and screen interpretation are BLOCKED. Owned
native screenshots taken for this review are not an implemented awareness
pipeline. Webcam and unrelated-screen capture were not performed.

Cluster: all eight configured nodes returned real CPU/RAM/uptime SSH telemetry
over Tailscale in the final observation. Refresh is one second; history is 60
seconds. Yunjin remains under repair with the requested jellyfish. Read-only
telemetry passed; reboot/sleep/terminal execution received no live acceptance.
The final fixture may expose available reboot/terminal buttons; no action was
invoked. Unsupported node sleep states stay unavailable.

## Native desktop evidence and limits

The actual Windows native client was exercised at 1920×1080, 1440×900, 1366×768
and compact 900×650 physical sizes, with measured 125% DPI. Final visible-frame
recapture contains 77 frames and 163 checks for all 18 primary screens, with no
JavaScript errors or unexpected external/unsafe requests. Separate populated
interactions passed 44 checks/11 frames; Mini passed 12 checks/six frames. Counts
include geometry and are not percentages of every implemented control.

The review covers navigation, dialogs, scrolling, palette/Escape, inspector,
capability search, synthetic project/note/task writes/readback, memory proposal
approval/correction/deletion, disconnected providers and safe cancellation.
Unavailable voice/vision remain honest unavailable states. Every settings
mutation, tray action, remote control and speaker operation was not exercised.

no unrelated process was terminated. Complete functional acceptance remains
partial even though the primary visual gate passed.

## Performance and reproducibility

Baseline original-controller latency P50/P95: 1.665/3.874 seconds across 172
turns, 331 genuine inference requests. Final unseen median: 1.718 seconds; mean
1.838 seconds over 24 turns/45 actual requests. Final requests ran once after
source freeze, without model switching or tuning the sealed expectations.
Initial cached STT model load was about 2.125 seconds; generated-silence decoding
took about 1.847 seconds before the exact-silence fix. The supervised capture
duration is not a recognition latency.

Final lifecycle checks launched the accepted original controller/model, inspected
real health/telemetry/registry and the isolated empty-vault state, then used
authenticated shutdown. All seven owned launcher cycles and the actual SDK
fixture process closed; exact owned PIDs and endpoints were checked absent.
All four production configuration hashes remain unchanged. Historical v1 working
bytes match their pre-migration digest; Git's canonical LF versus the existing
Windows CRLF checkout is explicitly recorded. No old behavioral corpus content
or protected configuration/LAYA evaluation path changed.
