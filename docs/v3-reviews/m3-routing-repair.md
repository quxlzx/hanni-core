# M3 bounded discovery repair candidate

Independent service cycle 1 found a genuine limitation: the original task
collection menu omitted the more precise registered `todo.get` readback.
The separate browser fixture found that an explicitly allowlisted local
file-creation request discovered no eligible action. Public descriptions,
bindings, expected outcomes and evaluation inputs were not changed.

Only `src/hanni/mcp/host.py` production code changed. The read widener now accepts
a strongly supported alternative sharing one object term when both capabilities
belong to the same registered namespace. Unrelated namespaces retain the
previous two-shared-term requirement. Ranking scores, statistical index,
correction rules and existing evidence thresholds were not retuned.

The original resolver/menu/prototype and strong lexical discovery order remain
first. If an explicit positive action has no eligible original action candidate,
a separate metadata fallback can discover explicitly allowlisted builtin local
reversible writes with strong evidence. Imported/provider external actions are
excluded. A strong original action discovery is preserved when it passes those
same bounds. This offers a menu, never consent: the original schema, actor,
confirmation, risk, read-only and background execution gates remain authoritative.
The workflow engine and other backend production files stayed frozen.
