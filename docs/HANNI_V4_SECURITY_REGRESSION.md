# V4.0 security and regression gate

The original controller, capability registry, MCP host, permissions and workflow
execution receipts remain authoritative. Adaptive selection places pure inference;
it does not create a second tool router or grant remote execution authority.

## Verified safeguards

The independent controlled selection matrix passed **48/48** valid selections or
correct refusals across four policies, six context categories and local-only
on/off. Tested privacy violations and context overclaims were both **0**. These
are bounded controlled results, not universal guarantees. The independent suite
passed **73/73**, including the final additive resource-history audit.

Eligibility checks health freshness, exact identity, authorized context categories,
supported transport/capability/format, aggregate messages/schema/output limits and
measured load. Manual policy applies the same checks. Remote workers retain their
existing synthetic-only categories and pure-analysis transport. Unknown vision,
90K/128K context and remote native-tool requests cannot become eligible from API
compatibility, successful format discovery, model confidence or configuration.

Fallback is bounded to pure inference and repeats original admission checks.
One independent uncertain-write fixture invoked its controlled handler exactly
once. No real side effect was executed in that fixture. Completed local streaming
preserves the original behavior; partial output is never replayed. Native and
local callbacks inherit their admitted output budget.

The new desktop API retains the existing Host/Origin/token protections. Policy
changes use a fixed reversible-write capability, UUID deduplication and Safe Mode.
Ten focused private HTTP/control tests passed, including wrong/missing tokens,
cross-origin calls, forbidden capability/privacy fields, request-ID collisions,
Safe Mode and shared-service ownership. Refresh requests return immediately and
wake bounded background health checks. They do not start model servers.

Remote evidence binds full configured model/backend file contents and runtime
settings. Local evidence binds full GGUF contents and reported runtime/build/
template/settings; local executable contents are not independently fingerprinted.
Same-build local binary replacement can therefore retain a local receipt. This
limitation is disclosed rather than claiming stronger identity protection.
Remote read-only fingerprint roots are restricted to existing configured files;
the narrowly scoped Strata addition has a protected backup with preserved ACLs.

Routing persistence contains settings, identity-bound measurements and bounded
decisions, without raw prompts, model answers, memories or credentials. Resource
history records known headroom/load at admission, not peak process consumption or
minimum model requirements. Unknown observations remain null and cannot inflate
accuracy. Old measured receipts remain compatible.

## Regression and packaging

The first broad integration run exposed two compatibility issues: the K2
comparison profile needed equivalent routing defaults, and the old CLI mock
provided health JSON in place of model discovery. The fixes preserve profile
equivalence and streaming assertions, with realistic model discovery and a
controlled 8K fixture. No actual identity was fabricated to pass the test.

The final complete run against frozen production source passed **1,840 tests,
2 skips and 25 subtests in 280.88 seconds**. The receipt is
`data/v40-manager/final-regression.xml`; the coordinator summary is
`data/v40-manager/final-verification.json`. Three supplemental independent tests
were added after that run collected its tests; they are included in the separate
final **73/73** independent result. The counts are not added together. The final
resource-history addition also passed **131 focused checks**.

TypeScript and packaged frontend assets build successfully. Wheel construction
includes `hanni.compute`, the adaptive engine, private routing API/view, and the
offline Geist font/license. Archive imports and asset/license checks are recorded
under `data/v40-manager`; the final release archive was verified after source freeze.
No private `data`, deployment credentials or configuration are included in the
wheel. Every packaged source/static file matches the working tree. The archive is
`data/v40-manager/package-release/hanni-0.10.1-py3-none-any.whl`, SHA256
`4512b966b8fb894c37bed10c63926c9cf76fcad53c905f94199d3681fd28a1a9`.
The existing font CSP allows the bundled data font without broadening
script or connection permissions.

Independent headless Edge review passed **9/9** interactions and scored **8.8/10**
at three viewport sizes. Display telemetry was explicitly a synthetic fixture;
policy writes exercised the real isolated API. Native desktop screenshot review
is not claimed.

## Actual operating limits

The sealed holdout passed 3/6 adaptively versus 2/6 on the resident default,
with higher latency and one rescued fallback out of four requests needing retry.
No meaningful simple-task latency improvement or general model superiority was
established. The original controller passed four real verified read-only tool
receipts across fixed/adaptive arms. Full autonomous WorkflowService readiness
is not inferred from those bounded reads.

The custom HANNI 4B candidate cannot load because a tensor is missing. GPU IQ3_S
weights requested in the intended deployment are absent; installed Q4_K_S weights
were measured accurately. All benchmark-owned serving processes and ports were
closed. The original Strata process/port and three original file hashes were
independently verified intact. No unrelated service was stopped, model downloaded,
primary replaced or repository pushed.
