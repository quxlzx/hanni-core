## Repairs and preserved authority

The authenticated shadow publisher originally followed a 302 to a second
owned loopback listener, forwarding the synthetic Authorization header. The
redirected GET carried no original POST body: the proof establishes credential
forwarding, not body transmission. The original manager health probe accepted
the redirected destination as health. Both now reject redirects. The existing
advisory client's redirect protection remains unchanged.

Closing a full shadow queue originally transmitted the pending second utterance
and lost the worker sentinel. Admission and close now share a lock; close
discards pending payloads and reliably signals termination. An already admitted
request may finish. The implementation does not claim to retract bytes already
sent or synchronously wait for network completion.

Direct session reads now revalidate current content, all serialized provenance
and metadata, semantic status and confidence. Imported confidence must be a
finite integer or float in `[0,1]`; booleans and coercible strings are rejected
at this record boundary. Confidence remains explicitly uncalibrated. Unsafe
legacy records and newly registered secrets are withheld with a truthful
message, without modifying the database. Project locations must also agree
with an explicit fact extracted from validated content. Owner deletion remains
available for quarantined rows, but its receipt does not echo their unsafe
content.

Session mutations now honor the original provided registry's owner profile,
chat-only flag, disabled automatic-approval setting and emergency stop. A
standalone session retains the existing explicit owner-only API. Automatic
fresh-fact capture additionally respects the original desktop memory tier two:
owner levels zero/one deny automatic persistence, while explicit Remember and
Forget remain direct owner commands. Existing desktop literal-confirmation,
revision and schema gates remain intact. No authority is granted by a stored
statement, observer prediction or workflow context.

Project selection suppresses a shorter name only when its span is contained
within an explicitly mentioned longer name. Separate mentions and equal shared
aliases remain ambiguous. An unresolved continuation with multiple projects
offers choices; it does not choose by recency or infer a personal referent.
Unrelated playback, weather and unknown project requests remain unrelated.

Malformed dates, confidence encodings, unavailable SQLite files and broken
indexes now produce a clear memory-availability reply. Read failures cannot
claim successful writes or deletion. Only known memory-reader errors become
the dedicated availability exception; model admission/errors continue to
propagate. Project-selection clarification remains distinct. The native legacy
factory passes the configured token limit, and Safe Mode/outage fallback uses
the trusted provided retriever's budget instead of silently reverting to 4000.
Context limits use the disclosed conservative UTF-8 byte bound, not a tokenizer
accuracy claim.

The privacy gate additionally rejects imperative automatic-approval requests.
Negative prohibitions, documentation discussion, quoted labels and statements
that approval is disabled remain data. This does not add a general model
narrative guard or alter existing permission decisions.

Project packages now quarantine the entire unsafe record rather than redacting
its metadata and retaining the content as an approved fact. Safe provenance is
preserved, omissions are explicit and imported rows remain unchanged. Native
project context compares the complete current record against the package,
revalidates privacy and checks the current secret-registry revision. A content,
source or confidence change with an unchanged timestamp, a deletion, or a late
secret registration cannot leave the earlier memory line in the returned
context. Safe unrelated project records are excluded.

## Scope and remaining limitations

Only six owned production files change: memory `session`, `integration`,
`projects`, `privacy`, and LAYA `client`, `manager`. Owned `facts`, `advisory`,
`runtime` and dashboard `memory` remain unchanged. The other engineering worker
owns store/retrieval/intelligence repairs and their separate retrieval results.
The final manifest includes those dependency hashes for an auditable cohort.
Python files and tests use the repository's LF convention; `git diff --check`
passes for these changes.

Boundary checks cover explicit and automatic writes, tentative/transient
refusal, project decisions/ambiguity, corrections, cross-session continuity,
deletion, provenance, unrelated exclusion, privacy, timeout/disconnection,
corrupt/missing dependencies, small budgets, workflow checkpoint readback and
malicious instructions. A paused workflow checkpoint is read-only evidence;
verified outcome summaries require all three original verification checks to
be literal true and do not grant restart authority.

These passes establish the tested implementation boundaries. They do not
establish recall precision, answer quality, model calibration or a successful
production LAYA deployment. The 320-case development retrieval corpus and
private independent 120-case final corpus carry those distinct denominators.
The final corpus was sealed before tuning and is never opened by this engineer.
Manager-owned real model A/B results and integrated regressions remain separately
measured, including original resource-admission refusals. Owner configuration,
owner memory records and existing protected processes remain untouched.
