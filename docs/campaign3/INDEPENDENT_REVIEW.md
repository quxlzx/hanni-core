# Campaign 3 independent verification

**Independent final validation is complete; memory-quality acceptance was not achieved.**
The untouched 120-case holdout ran once in both arms. Recall@5 was 44.68%
for original legacy retrieval and 60.64% for optional deterministic context
retrieval, below 90%. The original project-resolver diagnostic was 66.67%,
below 95%. Forty final original model attempts were blocked before generation;
actual answer quality and LAYA benefit remain unmeasured.

The verifier is an actual separate Codex agent. The manager and two engineers
cannot inspect the private holdout prompts or answers during development. The
common evidence and isolation rules in Campaigns 1 and 2 apply; no separate
standalone common instruction document was located. No owner memory store was
opened, no production file was edited by the verifier, and no existing model or
service was started, adopted, killed or restarted.

## Measurement boundaries

Nineteen independent integration tests pass, including ten generic
harness/scorer checks and nine original security/recovery probe groups. The
final verifier XML is `data/campaign3-verifier/verifier-final-development.xml`.
Four additional original scoped collision/review controls pass with exact
unchanged-store denial receipts. The generic checks exercise original
retrieval, exact source references, correction/deletion/suggestion purge, stale
revision rejection, same-timestamp external changes, whole-record budgets,
failed positive denominators and separate unmeasured response requirements.
An initial incorrect proposal argument keyword was a verifier harness error;
its failed XML is retained. Other exploratory errors involving conflicting
keyed facts, Windows trace cleanup and malformed fixture import/cleanup are
retained and are not product failures. An exploratory use of a nonexistent
`review` method was corrected to the original `review_suggestion` API; that
earlier attempt is likewise a verifier fixture error.

Recall is unique relevant IDs among the first five divided by every eligible
annotated relevant ID. Failed and missing cases stay in the denominator.
Precision divides relevant IDs by actual returned IDs; empty positive results
have undefined precision, not a perfect score. Negative abstention and exact
project status/candidate identity have separate denominators. Original project
resolution is a diagnostic boundary, separate from automatically selecting a
project in a native session. Explicit fixture scope is disclosed.

Retrieval latency excludes project diagnostics and setup. UTF-8 bytes are
conservative bounds, not actual tokenizer counts. Pure store setup, approved
corrections and deletion are distinct from unauthorized writes. Zero
retrieval mutations is not proof of all production permission boundaries.

A is the current original legacy retriever; D is the optional deterministic
context retriever. Neither is LAYA inference. Controlled original advisory
timeouts/disconnections test fallback contracts and are labeled as fixtures.
Actual LAYA B remains unavailable while production consent and quality gates
are closed. No response accuracy, causal conclusion, current-state proof,
actual workflow outcome or model-granted permission is scored as verified from
retrieval alone. Those requirements remain explicitly unmeasured until actual
response/action evidence exists.

The manager's final integrated regression has 463 passing checks; the separate
verifier suite has 19. These checks establish their stated implementation and
measurement boundaries, rather than recall or generated-answer acceptance.
The actual running owner application was preserved and was not restarted to
load this source. Production context retrieval and LAYA advisory/retrieval
remain disabled; no owner store, model, process or permission configuration was
changed by the verifier.

## Retained failure analysis

Recall omissions dominate: A fails full relevant-ID coverage on 51 queries and
D on 36. Returned ineligible or explicitly excluded IDs occur on seven A and
eight D queries; negative abstention fails on three and four respectively.
These overlapping checks must not be summed as distinct failed scenarios.

All failed source-reference, status and current-content checks correspond to
missing recalled records, rather than wrong fields on an actually returned
record. A has 5/8/11 such failed checks, D 4/6/8 respectively. One authored
oracle simultaneously excludes a record and requires its status in returned
records. This internal contradiction remains a literal failure in both arms;
no oracle or grade was rewritten. It does not affect recall, precision or
project-resolution counts. The report separates this annotation limitation
from product behavior.

The six failed project-status diagnoses comprise four required ambiguities
reported as none, one expected match reported as ambiguous and one expected
match reported as none. Exact candidate and identity checks also fail on
these scenarios. The broader ambiguous-reference problem remains unresolved;
these resolver receipts do not establish what a generated answer would say.

All six final controlled outage scenarios per arm avoid retrieval exceptions.
D actually reaches four original advisory fault boundaries. Two have no
eligible candidates and make no advisory request; their exercise-required
checks remain failed. A makes no advisory requests by design. Passing exposed
original timeout/session/Safe Mode boundaries is separate evidence, not a
live LAYA-quality result.

## Controlled lifecycle and budget evidence

Per arm, original isolated APIs execute thirteen corrections: eleven succeed
with exact result/readback agreement; two planned privacy/conflict rejections
leave records unchanged. Seven deletion attempts all succeed, with the target
absent from original store readback and final recall. Two annotated history
purges, one pending-suggestion purge and two unrelated-record retention checks
pass. Three statement analyses and one proposal leave authoritative records
unchanged. Ten store restarts, three index drops, two cache-tamper fixtures and

Four corrected targets and four deleted targets were actually recalled during
pre-mutation warm queries. This bounds direct invalidation evidence. The one
explicit cache-authority oracle ends with no returned record, leaving its
field-comparison dimension unexercised. Empty results cannot prove correct
current recalled content. Independent exposed-development cache, same-timestamp
and late-project tests supply additional original-path evidence. General
permission enforcement comes from the separate denied-profile/tier probes,
not these approved fixture operations or zero retrieval writes.

All six authored small-budget cases per arm remain within original character
and UTF-8 byte bounds. Three explicitly annotated whole-record checks also
pass literally, but all three receive empty contexts: populated-record
serialization is unexercised in those final checks. Original exposed-development
controls provide separate populated-record evidence. Budget compliance does not
imply adequate recall. Final primary context
