# HANNI Tool Intelligence V1 implementation report

The existing registry remains at **150 capabilities**. The deterministic routing benchmark now covers **1,087 cases** and scores **99.82% strict pass**, **99.66/100 average**. All capabilities have direct routing probes and are either reachable or intentionally blocked under the current permission policy. The only two strict failures expose `spotify.status` and `spotify.launch` alongside `spotify.play_pause`; those are plausible playback-support tools, so no phrase-specific router exception was added. See the [current routing baseline](../evals/routing/BASELINE.md), [full report](../evals/routing/after.json), and [coverage audit](../evals/routing/capability-coverage.json).

Calendar routing now resolves owner-local dates and event times through `user.timezone` in `config/hanni.yaml`, an IANA timezone. The configured repository owner timezone is `America/Chicago`. Google Calendar date windows use the same zone, including DST. Tests inject their timezone and cover normal, nonexistent, and ambiguous wall times. Neither the host OS timezone nor a fixed UTC offset determines benchmark Calendar arguments.

The [150-case LLM Tool Eval](LLM_TOOL_EVAL.md) uses the production router, MCP menus, model client, and bounded tool loop, while returning only deterministic synthetic tool results. It cannot invoke a real capability handler. Reports separate routing, model selection, arguments, reasoning, stopping, safety, and mock/runtime failures. The configured Qwen3.5-4B remains the production model; a separate single-model config directory can select another benchmark model without replacing it. Historical Qwen summaries are in [`evals/llm_tools`](../evals/llm_tools/README.md), while full local transcripts and checkpoints stay in ignored `data/`.

The final live Qwen run passed **124/150 tasks (82.67%)**, below the >85% target. Diagnostics passed 68.89% and mixed-domain requests 60%; conversation, files/search, and safety each passed 100%. Hallucinated-tool and unsupported-claim rates were 0% under the corrected rubric. Nine safety cases were stopped by policy before model inference. The task-success result varied between 81.33% and 82.67% across hardening reruns, so the system is **not ready to freeze** as Tool Intelligence V1. See the [final sanitized report](../evals/llm_tools/BASELINE_QWEN35_4B_FINAL.json) for hashes and family metrics.

The tool prompt was kept small: broad observation before a contributor check when diagnosing a bottleneck, disk I/O as a plausible explanation for slow loading even with healthy CPU/RAM, and evidence for every part of a mixed request. Destructive requests classified as blocked return a fixed refusal without a fallback model call or operational workaround. Benign questions about HANNI's permissions remain answerable. No new capability or registry entry was added.

Google account commands remain `hanni google login`, `status`, and `logout`, with mocked OAuth tests and Google dependencies in the normal install. A real account connection was not performed as part of the benchmark. No remote push or publication occurred.

Final validation: **427 tests passed, one skipped, and 17 subtests passed**. The skip is the PATH-dependent installed-entry-point test in this uninstalled checkout. Routing passed 99.82% strict over 1,087 cases, and the 150-case mock/route audit found zero errors. The three Google command help surfaces and the benchmark/model-comparison CLI help surfaces were checked. The workspace contains no `.git` metadata, so no commit identifier is available for this run.
