# Four-model sandbox integration candidate

The supplied architecture is implemented as an opt-in source integration, **not a verified cluster deployment**. Qwen3.5-9B is excluded at the owner's request. No models were downloaded, defaults changed, cluster objects applied, private listeners broadened or inference services restarted. Original Phase 3 failures and source archives remain intact.

## Boundaries and actual source path

The resident assistant remains the ordinary text/voice path. `/api/tasks` and `/api/tasks/<workflow-id>` alias the existing private workflow API, with the same token, origin protections, controller, approvals and durable request deduplication. There is no competing universal API server or second workflow database. The four external harnesses execute only within a separately authorized CPU sandbox; this exception to the earlier single-executor requirement follows the owner's explicit sandbox instruction.

`cluster.task_preview`, `cluster.task_submit`, `cluster.task_status`, `cluster.task_result`, `cluster.task_cancel` and `cluster.task_cleanup` are registered through the original tool registry **only when** the private sandbox deployment file exists. Submission, cancellation and cleanup require exact confirmation, tier-3 permission and audit. Discovery confers no authority. A preview is bound to the entire deployment and task, including exact source snapshots, project/run IDs, roles and selected test argv. The original measured model engine must admit every selected specialist, including private context, current identity, capability and resources, before an external write. Source files are credential-filtered; this intentionally conservative filter may reject authentication-related source and needs an owner-reviewed alternative before such code can be supported safely.

One CPU job runs a real LangGraph graph: Flash manager → optional Nex/GPT Researcher → optional Swift/OpenCode → optional Mellum/Aider → explicit checks → Flash advisory review. The owner selects eligible roles; the model cannot allocate arbitrary hosts, change credentials, grant access or create extra jobs. These are requested role assignments, not claims that the Phase 3 accuracy/residency gates passed. Six workers can schedule these lightweight jobs through the configured labels; no dedicated CPU computer per model is required. Control Center continues owning model lifecycle.

The worker uses actual OpenCode CLI, Aider CLI and GPTResearcher library adapters. OpenCode shell/web tools are denied; editing is confined by the container filesystem. Aider disables git commits, automatic lint/test/shell suggestions, analytics and updates; automatic acceptance applies only inside the explicitly approved disposable sandbox. Selected checks run separately with real exit codes. Internet is disabled, so research is **local documents only**; public price/source research requires a separately reviewed restricted outbound proxy and authorization. The researcher may also require an authorized local embedding backend depending on the installed version. Errors remain errors; no public/cloud model fallback is configured.

The task-scoped inference route `/api/sandbox/v1/chat/completions` is added on HANNI's existing listener, retaining literal loopback Host/origin protection. It uses a short-lived random per-job credential, whose hash alone is journaled locally; the credential is injected into the exact job via a namespace Secret. It grants at most 20 bounded pure-inference requests to the selected registered model identities, no tools/task API/lifecycle authority, and a deadline of at most 900 seconds. It invokes the original AdaptiveModelEngine with fixed endpoints, project/conversation/sensitive provenance, admission rechecks and zero fallback. Cancel/emergency stop revokes leases; emergency stop then requests cancellation of exact owned jobs asynchronously. Remote cancellation remains best effort when connectivity fails. No owner dashboard token or model-service credential is handed to a harness.

**The current gateway cannot satisfy native tool-call turns used by OpenCode.** The original worker inference boundary explicitly lacks that capability. Such calls are rejected, rather than dropping tool arguments or falsely reporting success. Streaming and embeddings are also unsupported by this new bounded route. These are concrete integration blockers; source adapters are not evidence of successful external-provider execution. A future extension must preserve the original engine's identity, privacy, resource and validation guards and return valid model-turn receipts.

## Isolation, evidence and recovery

Generated jobs require gVisor or Kata RuntimeClass, non-root UID/GID 10001, read-only root filesystem, no privilege escalation, all Linux capabilities dropped, RuntimeDefault seccomp, no service-account token, no host paths, no GPU resource, CPU/RAM/ephemeral limits, a 30–900-second deadline, `backoffLimit: 0`, `podReplacementPolicy: Failed` and bounded concurrency. Submission checks Restricted Pod Security labels, the RuntimeClass handler, a Bound ReadWriteMany PVC the exact namespace resource quota, and the exact gateway-only network policy, rejecting additional namespace policies that could add egress. A dedicated namespace is required. API objects alone do not prove CNI enforcement or runtime isolation; live isolation tests must pass before enabling deployment. The CPU/sandbox node labels must be inspected on actual schedulable workers.

The proposed defaults are `hanni-k3s`, `hanni-sandbox`, and both `hanni.ai/worker-class=cpu` / `hanni.ai/sandbox-enabled=true`. They have **not** been verified against a real cluster. The PVC must map its root to the sandbox portion of `/srv/hanni/shared/sandbox/`, with pre-existing owner-provisioned `projects/<project-id>/inputs/` and `projects/<project-id>/results/<run-id>/`. Inputs mount read-only at `/snapshot`; the worker verifies selected source contents against the approved snapshot before copying into the isolated `/workspace/project`. The specific results directory mounts at `/results`. No job mounts the whole shared root or owner's project directory writable. The shared storage backend, directory ownership, anti-symlink behavior, quotas and per-project separation need live verification.

`/results/receipt.json` preserves bounded returned artifacts and actual check receipts; the final log line carries the same envelope. Result collection checks job UID/binding and artifact SHA256 and persists the receipt in HANNI's private journal. It never applies patches to an owner project. Apply reviewed artifacts through HANNI's original file tools and confirmations. A completed job, successful process, hash or model review **never becomes a successful goal claim**; every result has `task_complete:false`. Independent acceptance against the original goal remains mandatory, and Phase 2's failed completeness gate still blocks unattended use.

The durable submission intent is written before Secret/ConfigMap/Job creation. Lost/partial acknowledgments stay `uncertain`; the same task ID suppresses another create, including after process restart. Reconcile by inspecting the exact task, not by retrying uncertain writes. Cancellation and cleanup use Kubernetes UID preconditions. Cleanup requires observed terminal state, removes only exact owned objects, preserves durable results and returns uncertainty when an acknowledgment is missing. Job TTL is one day; ConfigMap/Secret cleanup remains an explicit confirmed operation. Once a job expires, missing-job reconciliation may require an operator to confirm resource identities; the integration does not guess ownership or delete unrelated objects. Expired scoped credentials are unusable even if a Secret remains.

## Local checks and measured results

On this workstation, `kubectl` and `$USERPROFILE/.kube/config` are absent. No kubeconfig credentials, worker nodes, storage claims, runtime/CNI enforcement or gateway network route could be verified. **Live deployment is disabled.** Source example values and image digests are placeholders, not discovered infrastructure. The loopback controller is not directly reachable from CPU pods; an existing authorized private route must preserve its loopback Host protection and task credential, without exposing the service publicly or installing another model server.

Offline manifest validation passed. Final controller/boundary regression: **160 passed, 13 subtests passed, one optional graph module skipped** (4.21 seconds). With the isolated real LangGraph dependency, **two graph tests passed**. The Phase 2 regression also passed **332 tests plus 13 subtests** (22.11 seconds); these suites overlap and must not be summed as unique tests. Controlled tests cover path/credential rejection, exact preview binding, privacy/identity admission, disabled deployment, confirmation before effects, unknown-job exclusion, UID cancellation, no duplicated uncertain creates after restart, restricted job/network manifests, task-token scope/budgets/revocation, artifact hashes and false-completion rejection. The real optional LangGraph runtime was installed only into ignored `data/cluster-harness-validation/python-deps`; its two graph tests use controlled provider seams and prove ordering/provider-failure behavior, **not real OpenCode/Aider/GPT Researcher execution**. The current resident and model settings are unchanged; no new live latency or task-completion score is claimed.

## Deployment sequence and rollback

1. Inspect actual kubeconfig context and read-only cluster inventory. Confirm the proposed names, exact CPU node labels, Kubernetes version support for job replacement policy, Restricted admission, verified gVisor/Kata isolation, and enforced network policy.
2. Inspect the shared storage backend; provision exact per-run result directories separately with owner-approved ownership and quotas. Use a reviewed RWX PVC; do not introduce hostPath mounts.
3. Review the original controller gateway route and its task-token boundary. Extend and independently validate native tool turns/streaming required by OpenCode, and local document/embedding support required by GPT Researcher. Validate an existing private connectivity path; do not expose model services or give jobs the owner token.
4. Build an owner-reviewed CPU image from pinned dependencies; verify actual SDK contracts, constrained tools, token isolation, malicious-source behavior and bounded outputs. Resolve Swift resource evidence and model quality gates before promotion. No role assignment bypasses those gates.
5. Create or review dedicated namespace security resources using the original authorized infrastructure process. Never overwrite existing resources based on this example. Generate the exact network policy via `validate_cluster_harnesses.py`, review RBAC for only required namespace objects plus read-only namespace/RuntimeClass evidence, and run server-side validation and live isolation checks.
6. Only after all checks pass, place the reviewed private JSON contract at `data/cluster-harnesses/deployment.json` and explicitly enable it. Attach the ordinary HANNI controller; preview a specific task and confirm submission through original tool controls. Validate result hashes and independently test the delivered artifact before any owner-project application. Use fresh positive/negative cases; do not erase old failures.

Rollback: disable the private deployment and revoke/cancel live scoped jobs while their exact identities are still available; disabling first prevents the current cancellation handler from connecting, so cancel before disabling when possible. Restore only this integration's source changes in an isolated checkout, preserving Phase 1–3 and unrelated edits. The added task aliases can be removed without migrating workflow storage. Preserve journals and collected results for uncertainty reconciliation; never auto-delete owner inputs or reset databases. A source rollback requires your normal separately authorized service deployment procedure; none ran here.
