# Campaign 10 fixed acceptance protocol

Scope: integrated acceptance of the current HANNI implementation, using the actual configured local model where safely available. No major new features. Preserve all prior campaigns and owner stores. Physical audio testing is blocked by the user's stated device unavailability. Do not request further user actions.

Development: at least 100 prospective realistic tasks, authored before their execution, with separate input and oracle files. Core owns 63 standalone tasks; Systems owns at least 60 cross-system tasks. Independent final acceptance: 45 genuinely new tasks (three in each requested family), sealed by the verifier before tuning. Engineers and coordinator must not inspect private final inputs or answers. Final execution requires a frozen source/helper/dependency manifest and a single-use final admission claim. Development failures and unsuccessful harness attempts remain preserved.

Every task records these exact dimensions: `intent`, `retrieved_context`, `tools`, `arguments`, `authorization`, `execution`, `outcome_verification`, `final_response`, `latency`, `recovery`. Values distinguish PASS, FAIL, BLOCKED, NOT_MEASURED, and NOT_APPLICABLE, with evidence. Never infer model intent, selection, or response accuracy from service-only calls or a mock model. Preserve actual model output and original service readback.

Input-only shared envelope: `version`, `id`, `family`, `difficulty`, `description`, `user_turns` (prompt, actor_profile, confirmed), `fixtures`, optional bounded fault profile, and `actions` (operation, args, bind). Core's equivalent category/query/setup/actions contract may be normalized without reading or supplying oracle values. Public operation dispatch invokes original implementation classes; never dispatch on case IDs or expected results. Separate private grading owns expectations.

Evidence categories: LIVE_READ_ONLY, LIVE_MODEL_ISOLATED_SERVICES, ISOLATED_IMPLEMENTATION, MOCK_DEPENDENCY, BLOCKED, NOT_IMPLEMENTED, NOT_RUN. A task may have multiple categories; report its weakest essential dependency. Passing isolated services is not a live external integration pass. Unsafe operations use disposable fixtures or inert leaves, with original permission and scheduler boundaries retained. Calendar uses isolated local storage; no Google success claims. No real credential fixtures, personal screen capture, package installs, node reboots, or unrelated process termination.

Fixed targets: 100% registered capability inventory coverage; >=95% verified completion of eligible controlled core workflows; >=95% model tool selection on the untouched holdout; no known critical security failures; no fabricated completion; no significant unexplained regression; HANNI OS visual quality >8.5/10. Unsupported or blocked major subsystems remain visible in full-suite results, and may not be relabeled as passes. Every exclusion from eligible metrics needs a prospective reason. Latency P50/P95 and token usage reflect only measured executions. Historical measurements must keep their original denominator and evidence scope.

Actual inference is exclusively coordinated by the main agent: verified configured loopback model identity, fresh process/idle-slot checks, >=3 GiB available RAM and <90% used before each admission, one sequential request stream, temperature zero where supported, maximum 256 generated tokens per model request, at most three model requests per task, 45-second individual timeout, bounded batch duration. Maximum campaign generation budget: 450 admitted requests. On failed admission preserve NOT_RUN/BLOCKED evidence; never substitute teacher answers. Do not mutate these limits to force success.

HANNI launches as the actual current controller/backend plus packaged Windows desktop, with a fresh campaign-owned data directory and the existing configured model. Existing owner backend/model identities are preserved unless an explicitly required normal HANNI lifecycle step is documented. This is an acceptance instance, not a claim that the already-running owner backend has loaded changed source.

Repairs require a reproduced defect, independent before/after review, development regression checks, and a checkpoint. No tuning after final claim. Final report must compare C1–9 and authentic available pre-campaign baseline evidence without pretending unlike denominators are comparable. Publish complete outputs, tool traces, source manifests, verifier records, blockers, and continuation instructions when unfinished.
