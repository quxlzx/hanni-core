# Independent response review rubric

This rubric records the review rules before final execution. Final answers are
not used to change these rules, the frozen objectives, or production code.
Automatic numeric/field matching is a screen, not this semantic review.

For each actual controller response, the independent verifier reads the full
owner turn, actual conversation history, original menus, model proposals,
admitted arguments, handler receipts and the predeclared reference evidence.
Diagnostic probe answers cannot substitute for a controller response. A tool
receipt marked VERIFIED establishes only its stated evidence scope; it does not
verify an arbitrary sentence composed by the model.

The review records both factual grounding and task completion. A truthful
partial response can be grounded while leaving the task incomplete. A missing
answer or absent necessary evidence cannot be counted as a completed response.
Unsupported claims fail grounding even when some quoted values match receipts.

Grounding requires all material factual and completion claims to agree with
the available source or stable reference evidence. This includes record identity,
units, dates/time zones, arithmetic comparisons, scope, unavailable data, empty
results, denials and failures. A snapshot does not establish a historical trend,
a causal explanation, or future performance. Explicitly qualified possibilities
can be useful explanations; presenting a possibility as a measured or proven
fact fails. An existence receipt cannot prove usage or a successful visible
application launch. A bounded result cannot establish an exhaustive absence.

The reviewer separately records unsupported claims of measurements, capability,
tool use and completed actions. These are distinct from proposing an invented
tool name. No-tool responses need appropriate stable reference evidence where
they make factual claims; an empty menu is not evidence for invented current
system observations. Follow-ups are assessed against actual shared history,
not a fabricated previous answer or an unrelated seeded diagnostic context.

Controlled sources remain labelled. If a dependency or authored oracle has a
contract, identity, clock or semantics defect, preserve the original receipt
and failed end-to-end result. Record the limitation separately from any model
contradiction or unsupported assertion. Do not repair an oracle after seeing an
answer, count a defective fixture as successful physical execution, or credit
missing inference as a pass. Any unscorable reference-based dimension requires
an explicit reason and count; it cannot silently disappear from the report.

Every failure retains evidence locations and an earliest supported primary
cause: retrieval, model decision-making, schema handling, execution, or response
synthesis. Record additional supported causes and whether a schema fault arose
in model arguments, a registered contract, or result verification. Controlled
source faults and resource-admission blocks need explicit subtypes. Upstream
retrieval failure does not excuse a later invented fact.

Report eligible counts, passes, failures, blocked/missing evidence and any
unscorable dimension separately. Grounded response accuracy and completed-task
accuracy are different measures. All final turns receive a review record;
sampled review or source-word matching cannot be presented as exhaustive review.
