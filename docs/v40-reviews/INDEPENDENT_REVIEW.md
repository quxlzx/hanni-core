# HANNI V4.0 independent verification

Agent 3 independently designed the holdout, deterministic answer oracles, controlled regressions, live probes and screenshot review. The other agents implemented and integrated production changes. This review does not certify general autonomous reasoning: three of six difficult holdout tasks still failed after bounded adaptive retries.

**Disposition:** accept the routing safeguards and measured registry with the existing local default retained. Do not promote a different primary model from this small experiment. Keep externally checked reasoning and bounded fallbacks for authorized synthetic work. The custom HANNI 4B candidate could not load and remains unregistered.

## Evidence and separation

The new synthetic protocol was sealed before inference. Its SHA256 is `1d7f2cd5471dd7960bfa9b198fe1b9b0fea947d7f26146682d814746a2383ea5`. Each of four endpoints received two development cases and six previously unseen holdout cases. Development results were the only performance inputs available to the adaptive selector before its decisions were sealed. The holdout covered exact Bayesian arithmetic, stable priority ordering, shortest-path planning, a Python deduplication algorithm, a synthetic correction ledger and an unknown personal fact. Deterministic oracles checked the actual generated values; no model graded another model.

The final hardening check repeated the **same** six holdout cases in another fresh private routing database with current full-file identity proofs. It is a regression repeat, not a second unseen cohort. It again imported development-only performance before selecting endpoints. Production performance import occurred only after both adaptive runs were sealed.

All remote requests contained synthetic data. No real personal memory, screen, project or conversation context was sent to workers. HTTP compatibility, reported modalities and successful discovery probes were not treated as authorization to operate tools.

The initial full `python -m pytest -q` command exited successfully with two skips. Its double-quiet output did not retain a reliable numeric pass count. Existing font changes were pending and implementation began concurrently after collection, so this is a command-level baseline with a concurrent-source caveat, not a pristine frozen-tree claim. The coordinator owns the final full-suite regression result.

## Live fixed/default versus adaptive results

The first raw campaign made 32 successful transport calls, eight per endpoint. Settings were temperature 0, thinking disabled, maximum output 384, and no tool handlers. Holdout outputs were short, so the timing figures are observations for this protocol, not general throughput rankings.

| Fixed endpoint | Correct holdout answers | Median end-to-end response |
| --- | ---: | ---: |
| Existing local default | 2 / 6 | 280.4 ms |
| P6000 | 3 / 6 | 1,828.3 ms |
| P40 | 3 / 6 | 2,690.3 ms |
| Strata | 2 / 6 | 3,571.8 ms |

Every model passed the synthetic correction ledger and declined to invent an unknown personal fact. The GPU models also passed stable queue ordering. Every model failed the exact Bayesian answer, shortest path and Python algorithm cases.

| Adaptive comparison | Correct / verified | Median response | Aggregate response time |
| --- | ---: | ---: | ---: |
| Original unseen cohort, fixed local default | 2 / 6 | 280.4 ms | See original per-call artifact |
| First adaptive run | 3 / 6 | 3,286.4 ms | See original per-call artifact |
| Final strong-identity regression repeat | 3 / 6 | 3,793.6 ms | 20,563.9 ms |

Both adaptive runs rescued the queue-order case on the P6000. Four of six requests needed fallback; one of those four was rescued, a **1/4 fallback rescue rate**. Three requests exhausted the bounded three-attempt budget and were rejected. A final failure record whose destination is null is not an additional successful fallback. The two easy successful requests remained local without fallback. The adaptive improvement is one additional correct answer on this cohort, with substantially more latency; it does not establish broad model superiority or faster workflows.

Actual timing profiles depend strongly on context and environment. Short-output native generation measured approximately 79–84 tokens/s locally, 14.4 on the P40, 15.7–15.9 on the P6000 and 19–25 on Strata for the original holdout. At approximately 30.8K prompt tokens, cycle-A GPU generation fell to about 5.69 and 7.70 tokens/s respectively, and complete context requests took roughly 168–231 seconds across the two GPU cycles. Native server timings, complete wall latency and controlled fault simulations are kept separate.

Production now contains four identity-bound capability/context proof rows and 32 deduplicated measured samples, imported through engineering APIs after decision sealing. No preferences database was copied. Every task profile remains insufficient for a statistically supported quality promotion: these one- or two-item category samples are well below the engine's 20-item threshold and confidence gate. Configured policy, primary model and worker synthetic-only permissions remain intact. Ordinary ungraded runtime measurements are not counted as correct or incorrect answers.

## Independent controlled regressions

`tests/integration/test_adaptive_v40_verifier.py` completed **73/73 tests**, no skips, including three final resource/stream regressions. The deliberately controlled endpoint-selection matrix completed **48/48 valid selections or correct refusals (100%)**, across four policies, six privacy categories and local-only on/off. This exceeds the requested 95% controlled threshold; it is not a claim that arbitrary real-world decisions are 100% correct.

Covered behaviors include private fallback isolation, unknown or oversized context refusal, unknown vision refusal, manual override limits, stale health, identity mismatch, malformed output, rejected returned model identity, combined message-plus-tool-schema budgets and no prompt/output persistence in routing telemetry. Controlled privacy violations were **0**; tested context overclaims were **0**. Unknown memory capability did not become eligible from a guessed model family.

Six same-alias/same-filename regressions changed actual file bytes, backend build, quantization, template or K/V cache settings. Previous capability, context and performance evidence was invalidated. A real original tool-session fixture with a deliberately uncertain write result invoked its controlled handler exactly once, with no remote inference or repeated side effect. It performed no real write.

Independent review found and reproduced a selected-client output-budget defect: a 31-token callback request inherited the old 768-token default. The engineer fixed the admitted client bound; the final regression passes. Remote native proof with manual selection is explicitly denied on analysis-only transport. Initial failing artifacts remain available, rather than being deleted from the audit trail.

The final additive telemetry review also confirmed that 25 ungraded resource observations cannot raise correctness confidence or replace currently unknown endpoint headroom. Closing a partial local stream released its active slot and underlying controlled generator without a fallback or replay. A partial stream failure also released the slot, recorded an ungraded error and kept unknown resource fields null. Controlled input, output and exception sentinels were absent from stored measurement and decision payloads.

## Resource observations and cleanup

These are observed allocations, not universal model requirements. The local 16K/q8 cache session logged about 2,571.63 MiB Vulkan model allocation, 272 MiB KV cache, 50.25 MiB recurrent state and 85.28 MiB compute buffer; its observed process RSS after the context probe was about 4.45 GiB. Each 24-GiB GPU had roughly 18.4 GiB resident usage with the tested 32K/f16 profile. Strata's host had approximately 64.9 GB total RAM and an AMD 16-GiB GPU, with about 8.97 GiB RAM and 293 MiB reported VRAM free at the sampled time. Configured budgets remain labeled separately, and unmeasured RAM/VRAM requirements remain unknown.

New runtime measurements may persist optional RAM available, VRAM free, current request count, queue depth and a sampled timestamp. Memory values come from the latest health/resource snapshot available when inference is admitted; load is the observed routing load before reserving that request. Per-field count/mean/min/max aggregates describe those snapshots, **not peak usage during inference or per-process/model memory requirements**. Ungraded local completion, cancellation and streaming failures do not acquire correctness labels. A read-only audit of the actual production registry confirmed all 32 earlier published rows remain readable and retain unknown resources. Replaying those exact receipts into an isolated database copy was idempotent for 32/32 rows; the production measurement rows were unchanged. This audit used stored identities only to check serialization compatibility, with no new runtime proof, model probe, startup or evidence reimport.

All owned local, GPU and temporary Strata inference sessions were closed through their bounded ownership helpers. Independent read-only checks confirm the local benchmark PID and loopback port are gone, both GPU benchmark PIDs and ports are gone, and no GPU compute process remains. The temporary Strata PID and benchmark port are gone. The original Strata PID 69299 and port 8765 remain live; the original launcher, private configuration and server source hashes are unchanged. No unrelated service was stopped.
