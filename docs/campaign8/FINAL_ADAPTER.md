# Campaign 8 final adapter scope

The private final inputs and answers were sealed before production tuning.
Their bytes remain unchanged. The final native application mounts a disposable
original production DashboardServer and isolated stores, because mounting actual
screens can initialize data or background observations even for GET requests.
It does not mount the owner's databases as writable fixtures.

The sealed input field `authority_mode: owner_read_only` means the verifier's
actions do not issue original HTTP mutations or authorize owner/provider effects.
It does not mean the native session connects to the owner data directory. The
native evidence class is CONTROLLED against original isolated service receipts;
bounded LIVE owner/backend identity and status projections are separate records.
This label clarification changes no private case, expected predicate or action.

The final covers route/layout, safe local UI/native window actions and displayed
backend truth. It does not prove that every CRUD action, streaming inference,
provider account or remote worker operates. Those require their own actual
original implementation receipts and eligible outcomes. A disabled original
capability is not a successful implementation merely because it looks disabled.

Every screenshot records native PID/creation, HWND, Windows DPI, physical window
size, source and shipped asset identity. CDP is an automation channel for the
actual WebView2 process; emulated metrics and CDP client-image fallback remain
separate from original owned HWND capture. Windows-wide scaling is not modified.

The executor receives only input objects. After exclusive claim and whole-source
freeze validation it runs the complete sealed set once, preserving every failure,
unsupported operation, missing observation and resource block. Grading reads
private answers only after raw observations close. No final retry, promotion or
oracle-guided source change is allowed.

The public input collector is
`scripts/campaign8_verification/final_runner.py`. Main cases without an explicit
size start at a physical 1366 by 860, and Mini cases at 620 by 640. Each case
starts by closing local dialogs with Escape, selects its declared original route,
and applies its authored physical size. Layout observations include a bottom
scroll and additional owned-HWND capture where a scrolling region exists. The
original WebView accessibility tree supplements DOM names; empty DOM text alone
cannot diagnose an unnamed input with an associated label.

The Mini show/dismiss action uses the original owned HWND and bridge. It captures
the visible intermediate window before dismissal and records the hidden result;
it does not pretend this tests Application menu, tray or a global shortcut.
Original API evidence comes only from a fixed GET whitelist, using the original
ephemeral dashboard token held in memory and never written to evidence. The
owned backend PID/creation identity is checked before and after that readback.
Layout scrolling targets the main content or its containing scroll region,
instead of an unrelated navigation scroll area. Whole-case durations include
actions, original API/DOM/accessibility observations and owned HWND captures;
native startup and teardown are separate. Native requests and
owner service identities are recorded separately; process identity equality is
an observed before/after interval, not continuous monitoring. No requested action
sends a conversation, starts or stops an assistant, dispatches voice controls or
executes an external capability.

Post-close grading requires one independent review for every case, each binding
the exact raw receipt SHA. Missing evidence remains unmeasured and cannot pass.
Frozen boolean/string/count predicates compare exact values without bool/int
aliasing. A predicate explicitly ending in `_max` is an upper bound, not a demand
that the observed value equal the maximum. Manual failure classifications do not
change the original pass/fail criterion. Full visual acceptance remains separate
from these functional predicates and uses the fixed screenshot rubric.

The owner has explicitly stated that microphone and speakers are unavailable.
Physical wake, playback and interruption checks are BLOCKED. Controlled UI state
checks or device enumeration cannot establish acoustic success, and the final
does not activate any audio or capture device.
