# Campaign 5 independent review

The independent verifier sealed 100 new private tasks before production repairs,
ten in each of the requested ten families. Inputs, reference oracles, author code
and protocol remain in ignored private storage. Only hashes and aggregate counts
are shared with the manager and engineers. [FINAL_SEAL.json](FINAL_SEAL.json)
records that boundary. A hash-only comparison with the current 200 development
queries found no exact normalized last-user-message collisions; hash equality
does not prove semantic novelty by itself.

The independent controlled suite checks original adaptive, collaboration,
compute-bootstrap and client implementations. Its callbacks, capacities and
owned loopback HTTP responses are explicitly synthetic implementation fixtures.
They establish neither physical model quality nor real cluster availability.

Preserved evidence under `data/campaign5-verifier` includes the original
implementation failures, exact production bytes, original HTTP response
identity failures and every later independent verification cycle. The first
33-case run had 32 failures and one passing positive control. Two prospective
expectations were subsequently identified as oracle mistakes: a healthy expired
local lease may be renewed through the genuine original local probe, and a
queue becoming busy after dispatch must not discard an already admitted result.
The original run and assertion bytes remain unchanged. The corrected 34-case
pre-repair suite had 32 failures and two passes; its new expiry controls require
the genuine probe and distinguish healthy from unhealthy renewal.

Independent repair checks caught a remaining bootstrap GPU guard that treated
configured GPU device zero as false. The repaired guard distinguishes presence
from truthiness. The later 43 non-client checks passed. Nine separate original
client HTTP controls then confirmed that a present wrong model was originally
accepted for chat, native tools and late streaming output. Missing and matching
model responses were compatible. After repair all nine pass, including exactly
one POST and no replay after partial streaming output.

A further fresh late-streaming response showed that the adaptive layer recorded
the rejected replacement model as configured-model incorrectness. The repaired
classification retains an endpoint error, records correctness as unknown and
uses `model_identity_mismatch`; it does not penalize the intended model with a
fabricated wrong answer. The original attribution failure and later passing
independent control remain separate receipts.

The final inputs-only executor is
`scripts/campaign5_verification/holdout_runner.py`. It requires explicit manager
whole-final authorization, an exact source/configuration freeze, the unchanged
private seal and an immutable development checkpoint. It claims the whole run
once, exposes no subset/retry option and rechecks source membership and bytes
before every case and mode. Each case and mode receives a fresh complete SQLite
copy of development proofs, quality/timing measurements and collaboration
comparisons. Original current health/resources remain real observations. Final
unscored telemetry cannot affect subsequent tasks. No final reference verifier
is supplied to inference, selection, fallback or collaboration.

The frozen protocol applies `max_fallbacks=0` to individual baselines; native
adaptive fallback and selective collaboration retain their original configured
policy. An accepted prospective adapter clarification consumes the sealed
fallback and timeout metadata rather than forwarding unsupported generation
kwargs. Receipts retain the sealed limits, effective mode settings and original
client timeouts. The requested 120-second value is disclosed as metadata; it
does not override or interrupt an owner model process. Every arm receives the
same task messages, generation temperature zero, top_p one and prospective
256/512-token output budget.

Final tasks do not enable legacy-default admission. An empty development
checkpoint does not certify text, native functions, structured output or
context. Missing genuine capability/context proof remains blocked even if
resource headroom later recovers. Development legacy-path diagnostics and these
strict final tasks have different eligibility and must be reported separately.

Independent scoring is post-run in a separate publisher. Exact JSON checks
reject duplicate keys, nonfinite values, incorrect types and extra fields.
Coding uses prospectively authored AST-equivalent replacement references; no
model code executes, and unannotated equivalent patches can be missed. Native
function proposals are judged against original input schemas and the single-call
protocol. Plain text recommendations never become native calls. Supplied
synthetic memory evidence does not prove production memory retrieval. Tools and
workflows are not actually executed by these model tasks.

Raw original wire bytes are retained before the original parser. Accessible
completed responses rejected by the controller can be independently scored with
their original rejection outcome preserved. Identity-withdrawn, cancelled,
unselected collaboration, truncated or incomplete responses are not attributed
to configured-model factual quality. Zero actual generation HTTP produces null
semantic metrics and unconditional non-success, rather than a canned answer,
zero-token fiction or a model-factual failure.
