## M2 bounded contextual retrieval, 2026-10-09

Implemented: optional deterministic weighted lexical retrieval with bounded, complete provenance records; explicit project filtering; distinction between owner statements and verified records; suppression of hypothetical/inferred/temporary context; configurable record, character, and conservative UTF-8 byte token bounds. Records are read from the authoritative store for each request, with no persisted vector index or raw-text retrieval cache. Existing `LocalMemoryRetriever` remains the default.

Additional M1 coverage now retains completed claims, historical statements, failed claims, and temporary statements as unverified categories. Explicit primary-model declarations use a common fact key so a proposed change can identify a conflict without choosing the newer statement as true. The intelligence rules remain conservative proposals and explicitly uncalibrated; the legacy extraction path still announces direct owner facts.

New configuration: `memory.context_enabled: false`, `memory.max_context_tokens: 4000`, and separate disabled LAYA advisory/retrieval/consent settings. The token budget is a conservative byte upper bound, not a measured tokenizer count. Optional advisory ranking accepts only already validated, revision-bound results; it cannot block deterministic recall. Queued inference rechecks record IDs and revisions before dispatch, and optional-client exceptions fall back to local ranking.

Coordinator validation: 64 focused retrieval/configuration/intelligence/advisory/legacy memory and shadow tests passed in the latest combined run. Candidate A/B quality and performance remain pending the independent frozen benchmark; no measured improvement is claimed here. Genuine LAYA reranking remains NOT TESTED and cannot be enabled by the configuration flag alone.
