Important scope limits remain:

- Calendar success compares the returned resource's identifier/title/schedule against planned arguments. It does not independently derive tomorrow at 15:00 from a fixed clock or measure natural-language date planning.
- Task creation/completion, note append and file deletion enter an exact structured ToolAware boundary. Their genuine state/confirmation checks do not establish retrieval/model argument extraction for the user-language query.
- Application launch outcomes are controlled receipts or process probes, not real Windows application/window integration.
- Diagnostic values are controlled measurements. Separate real local read smoke results supply limited actual Windows integration evidence.
- An MCP call ledger establishes original-name execution, not an independent remote objective. A remote tool's self assertion remains unverified.
- The comparison's unauthorized-sensitive-execution metric is explicitly not measured when the runner has no count; it must not be displayed as forty observed zeroes. Separate independent gate tests supply actual denials/no-handler-entry evidence.
- Runtime latency includes per-case fixture/server setup and controlled execution. One paired pass cannot establish a robust live-model or voice speedup.

The comparator rejects changed case hashes, IDs, outcome kinds and stage schema. It fingerprints runtime packages, runner and fixtures before/after its own run, separates absent old verification records from failed outcomes, and reports Wilson intervals with denominators. Its pipeline pass percentage describes these exposed controlled expectations, not unseen generalization.
