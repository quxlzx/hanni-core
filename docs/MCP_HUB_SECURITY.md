# MCP Hub security verification

Backend acceptance: **PASS** for the implemented boundaries below. Independent full regression cycle 3 contains 964 passing tests, two existing skips and 17 passing subtests, with no failures/errors. It includes 81 MCP Hub cases: 32 manager/transport/store, 14 registry/execution, 11 authenticated API, and 24 independently authored adversarial/controller cases. Evidence and source hashes are in [M3 cycle-3](mcp-hub-reviews/m3-cycle-3.md); preceding failures remain in the checkpoint history.

## Scope and limits

The HTTP protocol integration tests use real local SDK Streamable HTTP servers. They verify authentication, errors, redirects and execution; no live external provider or public HTTPS service is claimed. DNS/TLS pinning is independently exercised at its guard boundary. Private/Tailscale remote MCP endpoints, automatic OAuth and automatic startup connections are not supported by this release.

Approved stdio programs run with the owner's OS authority; HANNI supplies no separate OS process sandbox. HANNI's permission gates control imported tools through its own registry. Normal observe-first conversations expose approved read-only tools. The tested write path is a trusted confirmed ToolRequest on the attached original registry; this phase adds no conversational confirmation/resume dialog or standalone imported-tool CLI. Unsupported schema constructs remain inspectable but disabled.

No node reboot/sleep, external provider write, production credential change, model training, package installation or publish/push was performed in this verification. The separate native acceptance gate is now passed: [final native review](mcp-hub-reviews/m4-native-cycle-2.md) verifies corrected controls, 92 actual framed images, real owned export content and 17 checks in each of two runs. [Final verification](MCP_HUB_VERIFICATION.md) records the complete acceptance result and remaining product limits.
